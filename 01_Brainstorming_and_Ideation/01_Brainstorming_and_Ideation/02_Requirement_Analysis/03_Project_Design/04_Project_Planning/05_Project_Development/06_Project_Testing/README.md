# Phase 6 – Project Testing

## Project Title
Streamlining IT Procurement – Automating Standard Laptop Orders with Flow Designer

## 1. Testing Objective

The objective of this phase is to verify that the automated laptop procurement workflow works correctly according to the requirements.

## 2. Testing Scope

The following components will be tested:

- Laptop request submission
- Request validation
- Approval process
- Approved request processing
- Rejected request processing
- Status updates
- Notifications
- Workflow completion

## 3. Test Cases

| Test Case ID | Test Scenario | Expected Result | Status |
|---|---|---|---|
| TC01 | Submit valid laptop request | Request should be created successfully | Pending |
| TC02 | Submit request with missing information | System should validate the request | Pending |
| TC03 | Approve laptop request | Workflow should continue to procurement | Pending |
| TC04 | Reject laptop request | Workflow should stop and update rejection status | Pending |
| TC05 | Check request status | Correct status should be displayed | Pending |
| TC06 | Check approval notification | Notification should be generated | Pending |
| TC07 | Check completion notification | Completion notification should be generated | Pending |
| TC08 | Complete approved request | Request should reach completed state | Pending |

## 4. Testing Method

Testing will be performed by submitting different laptop procurement requests and observing the Flow Designer execution and resulting request status.

## 5. Expected Results

The system should:

- Create valid requests successfully.
- Validate required information.
- Trigger the approval process.
- Continue processing approved requests.
- Stop processing rejected requests.
- Update request status correctly.
- Generate required notifications.
- Complete the workflow successfully.
